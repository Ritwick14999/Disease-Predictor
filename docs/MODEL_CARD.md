# Model card — Disease Predictor

Following the structure of [Model Cards for Model Reporting](https://arxiv.org/abs/1810.03993).

> **This model is not a medical device.** It was built to practise machine
> learning engineering on a public teaching dataset. It must not be used for
> diagnosis, triage, or any health decision.

## Model details

| | |
| --- | --- |
| **Developed by** | Ritwick |
| **Model type** | Multi-class classifier over 132 binary symptom indicators |
| **Default architecture** | Gradient-boosted trees (XGBoost), `multi:softprob` |
| **Alternatives** | Logistic regression, decision tree, random forest, and `SymptomSignatureMatcher` — a rule-based Jaccard baseline |
| **Output** | Ranked shortlist of diseases with probabilities and per-symptom attribution |
| **License** | MIT |
| **Version** | Recorded per artifact; see `GET /model-info` |

Each trained artifact records its own configuration, dataset fingerprint,
library versions and held-out scores. `dp info` prints them.

## Intended use

**In scope**

- Demonstrating an end-to-end ML pipeline: audit → train → evaluate → serve.
- Studying evaluation methodology, particularly duplicate-row leakage and
  leakage-aware split protocols.
- A worked reference for packaging a model as a tested, containerised service.

**Out of scope**

- Any clinical or self-diagnostic use.
- Any population, symptom vocabulary or disease outside this dataset's 41
  classes. The model cannot express "I don't know" or "not in my label set": it
  always returns a distribution over the 41 diseases it was trained on, and for
  a condition it has never seen that distribution is confidently wrong.
- Any setting where a wrong answer carries cost.

## Training data

The public *Disease Symptom Prediction* dataset. See
[`DATA_CARD.md`](DATA_CARD.md) for structure and known defects, all of which
materially affect how the metrics below should be read.

By default the pipeline **deduplicates before training**. Repeated rows do not
add information; leaving them in silently reweights the loss towards whichever
patterns happen to repeat most.

## Evaluation

Full detail in [`METHODOLOGY.md`](METHODOLOGY.md).

**Protocol.** The default is a *grouped* split: rows sharing an identical
symptom vector are kept on one side of the boundary, so test rows are patterns
the model has not seen. The alternative random split is also run, on raw data,
and the difference is reported as `leakage_gap`.

**Metrics.** Accuracy, balanced accuracy, macro-F1, top-3 accuracy, log loss and
expected calibration error — plus a robustness grid measuring accuracy under
symptom dropout and false-positive noise.

**Reproduce.**

```bash
dp train                    # real dataset in data/raw/
dp train --synthetic        # no dataset needed
```

Results land in `reports/metrics.json` and `reports/training_report.md`.

## Quantitative results

Numbers are **not hard-coded in this documentation**. They depend on your copy
of the dataset and are regenerated by `dp train`, which writes them to
`reports/`, embeds them in the bundle, and serves them at `/model-info`.

Read them in this order:

1. **The robustness grid.** Accuracy under symptom dropout — the closest thing
   here to a real-world estimate.
2. **The benchmark table.** If the rule-based baseline keeps pace with gradient
   boosting, the task is a lookup and the ensemble is not earning its cost.
3. **`leakage_gap`.** How much score the random protocol hands over for free.
4. **Headline accuracy.** Last, and only in the context of the three above.

## Limitations

- **The dataset is close to a lookup table.** Near-perfect scores reflect a
  clean, near-deterministic symptom-to-disease mapping, not diagnostic skill.
- **Closed world.** 41 diseases, 132 symptoms. Anything outside that vocabulary
  is invisible to the model, and it will still return a confident ranking.
- **Binary symptoms only.** No severity, duration, onset, progression, age, sex,
  comorbidity, medication or test result — all of which dominate real diagnosis.
- **No calibration guarantee.** Expected calibration error is measured and
  reported; it is not optimised.
- **No temporal or external validation.** The data has no time dimension and no
  second cohort to validate against.
- **Correlation, not causation.** Symptom weights are dataset associations, not
  clinical mechanisms.

## Ethical considerations

- **Risk of misuse.** Any symptom-checker output can be read as advice. The
  disclaimer is attached to every prediction — API response, CLI output and UI —
  rather than sitting in a footer.
- **Fairness.** The dataset carries no demographic attributes, so fairness
  across populations **cannot be assessed**. Absence of evidence of bias is not
  evidence of its absence.
- **Over-confidence.** A near-deterministic dataset produces sharp probabilities
  that look authoritative. The inference layer counters this by flagging
  low-confidence outputs, warning when fewer than three symptoms are given, and
  attaching per-symptom attribution so a ranking can be inspected rather than
  simply believed.
- **Automation bias.** The output is a ranked shortlist with reasoning, not a
  single verdict, specifically to discourage treating it as an answer.

## Maintenance

Retraining is a single command and every artifact is self-describing (dataset
fingerprint, config, versions, scores). There is no monitoring or drift
detection: this is a portfolio project, not a deployed system.
